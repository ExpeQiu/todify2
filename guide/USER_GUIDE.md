# Todify4 用户使用指南（上线版）

本文档面向业务用户、内容运营和系统管理员，帮助你在 Todify4 中完成项目管理、知识沉淀与 AI 共创。

## 1. 系统简介（用户价值）

Todify4 是一套面向技术内容生产的协作平台，核心价值是：

- 将“项目资料、技术点、来源信息、AI 生成内容”放在同一工作台闭环管理。
- 用项目上下文驱动 AI，对话、技术包装、技术策略、技术通稿在同一项目内连续演进。
- 支持公共知识库与技术点库复用，减少重复整理。
- 支持管理端配置（文章类型、Agent 设置、工具箱），保障团队标准一致。

## 2. 首次使用（3-5 步）

### 第一步：进入首页并确认导航

登录后进入首页，确认可见入口：

- 全部 / 我的项目 / 精选项目
- 公共知识库
- 技术点库
- Agent 助手

### 第二步：创建第一个项目

1. 在项目列表点击“新建项目”。
2. 填写项目名称与项目描述。
3. 点击“创建”后进入项目管理页。

### 第三步：补充项目上下文

1. 在项目管理页左侧添加或关联技术点。
2. 在右侧资源区补充来源信息（外部资料或历史沉淀）。
3. 确认项目已有可用上下文后，再进入 AI 共创页面。

### 第四步：发起 AI 共创

按需进入项目内的任一页面：

- AI问答：快速讨论和澄清问题
- 技术包装：生成结构化技术内容
- 技术策略：输出策略建议
- 技术通稿：形成可发布文本

### 第五步：回看与沉淀

回到项目管理页查看：

- 技术点是否完整
- 来源信息是否可追溯
- 对话与结果是否满足当前目标

## 3. 页面导航总览

### 3.1 首页

适合做项目入口与总览管理：

- 全部：查看全量项目
- 我的项目：聚焦个人项目
- 精选项目：查看重点项目

### 3.2 项目内页面

每个项目包含 5 个主页面：

- 项目管理：统一查看技术点、来源与对话关联信息
- AI问答：面向问题澄清与方案讨论
- 技术策略：面向策略和传播方向
- 技术包装：面向结构化内容生产
- 技术通稿：面向正式发布文本

### 3.3 资料管理页面

- 公共知识库：按分类维护公共文件与知识
- 技术点库：集中管理技术点，支持筛选与关联项目
- 来源管理：跨项目查看和维护来源信息

### 3.4 配置页面（管理员常用）

- 文章类型：管理可选文章类型与关联角色
- Agent 设置：管理可用 AI 角色
- 工具箱：管理字段映射与工具配置

## 4. 功能模块详解

### 4.1 项目管理

- 功能说明：管理项目核心上下文，是后续 AI 输出质量的基础。
- 适用人群：项目负责人、内容运营、技术编辑。
- 操作步骤：
  1. 打开项目后先进入“项目管理”。
  2. 在左侧检查技术点覆盖度。
  3. 在右侧补齐来源信息并查看历史对话。
  4. 对关键内容做统一校验后再进入其他页面。
- 使用建议：先整理上下文，再批量进行 AI 生成。
- 常见误区：直接生成内容但未补上下文，导致结果泛化。

### 4.2 AI问答

- 功能说明：用于问题澄清、方向确认、快速试探方案。
- 适用人群：全体用户。
- 操作步骤：
  1. 在项目内打开“AI问答”。
  2. 输入问题背景、目标与限制条件。
  3. 基于回答持续追问，形成可执行结论。
  4. 将关键结论回填到项目上下文。
- 使用建议：提问时带上“目标+对象+输出形式”。
- 常见误区：问题过于宽泛，无法得到可执行回答。

### 4.3 技术包装 / 技术策略 / 技术通稿

- 功能说明：三类页面分别面向“内容组织”“策略形成”“发布表达”。
- 适用人群：内容作者、市场运营、项目负责人。
- 操作步骤：
  1. 先在技术包装形成可复用的技术主干。
  2. 再在技术策略沉淀传播要点与落地动作。
  3. 最后在技术通稿完成正式对外文本。
  4. 对关键内容进行人工复核后发布或归档。
- 使用建议：按“包装 -> 策略 -> 通稿”顺序推进更稳定。
- 常见误区：跨页面重复输入且不复用已沉淀结果。

### 4.4 公共知识库与技术点库

- 功能说明：统一管理可复用知识资产。
- 适用人群：知识管理员、内容运营。
- 操作步骤：
  1. 在公共知识库维护分类与文件。
  2. 在技术点库新增或编辑技术点并打标签。
  3. 将已沉淀技术点关联到具体项目。
- 使用建议：分类命名统一、标签颗粒度一致。
- 常见误区：资料上传后不分类，后续检索困难。

## 5. 高频任务操作（按目标组织）

### 任务 A：新项目从 0 到 1

1. 创建项目。
2. 关联技术点与来源。
3. 在 AI问答确认方向。
4. 在技术包装生成初稿。
5. 在技术策略和技术通稿完成对外版本。

### 任务 B：把已有知识快速复用到新项目

1. 从技术点库筛选并批量选择技术点。
2. 回到项目管理页完成关联。
3. 在公共知识库补充新资料并关联来源。
4. 启动 AI 共创并验证输出一致性。

### 任务 C：统一团队输出标准（管理员）

1. 在文章类型页面维护类型与说明。
2. 在 Agent 设置页面启用合适角色。
3. 在工具箱页面校准字段映射。
4. 组织一次样例任务验证标准生效。

## 6. 常见问题 FAQ（用户视角）

### Q1：为什么 AI 输出不够贴合项目？
先检查项目是否已关联足够的技术点与来源，再补充问题背景和目标受众后重试。

### Q2：如何避免不同项目内容串线？
尽量在对应项目页面内发起对话与生成，避免在无项目上下文下直接产出正式稿。

### Q3：技术点和来源先维护哪个？
建议先维护技术点主干，再补来源证据；两者结合时输出质量更稳定。

### Q4：公共知识库和技术点库有什么区别？
公共知识库偏原始资料与文件归档；技术点库偏结构化知识条目与复用。

### Q5：谁可以改文章类型、Agent 与工具箱？
通常由管理员维护，普通用户以使用为主；如需调整请走团队配置流程。

### Q6：结果异常时如何快速反馈？
请按“项目名 + 页面名 + 操作时间 + 问题现象 + 截图”提交给管理员，便于定位。

## 7. 使用建议（提升效果）

- 先澄清任务目标，再发起 AI 生成，避免来回重做。
- 每次任务完成后，把可复用内容沉淀到技术点库或公共知识库。
- 对外发布前至少进行一次人工复核，特别是数据、术语和结论。
- 团队内统一命名规范（项目名、技术点名、分类名）可显著降低沟通成本。

## 8. 术语说明

- 项目：围绕一个业务目标的内容协作空间。
- 技术点：结构化知识条目，可跨项目复用。
- 来源信息：支撑内容结论的依据，包含外部来源和内部沉淀。
- 公共知识库：团队共享资料库，偏文件与分类管理。
- Agent：承担特定任务风格的 AI 角色能力。

## 附录：过程排查建议（日志记录）

为便于问题排查，建议在团队协作中统一记录以下信息：

- 基本信息：项目名、页面名、操作人、发生时间。
- 操作路径：进入页面后的关键点击步骤（3-5 步即可）。
- 输入与预期：你输入了什么，希望得到什么结果。
- 实际结果：是否报错、结果是否偏离、是否可复现。
- 佐证材料：截图或关键结果片段。

这样可以显著降低沟通成本，缩短问题定位时间。
